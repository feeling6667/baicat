# 数据复盘记录表 · baicat

> 每发布一篇填一行，长期迭代用。核心目标：
> 1) 追踪「光影+画纸变量」是否重复，避免跨篇撞参数；
> 2) 用发布数据反向优化脚本与流程；
> 3) **（V3）数据是唯一客观的"评分系统"**——发布表现反哺选题，AI 不参与判断。

## V3 数据反哺闭环（每 20 篇跑一次）

发布数据回填后，登记进 content_registry（含数据字段）：

```bash
# 把 completion（完播率）/ retention（划走率） / comments / shares 补进作品记录后：
python3 scripts/content_registry.py --registry data/content_registry.json register --file work.json
# 组合统计 + 按完播率排序：
python3 scripts/content_registry.py --registry data/content_registry.json stats --last 20 --with-metrics
```

AI 根据 stats 输出**组合分析**（不做主观评分，只报数）：

```markdown
## 近 20 篇数据反哺
- 高表现组合：〔人物关系 × 主题 × hook_type〕平均完播率 X%（共 N 篇）
- 低表现组合：〔……〕平均完播率 Y%（共 N 篇）
- 建议下批选题：向高表现组合倾斜；content_registry 的 limits 可据此收紧
```

> 关键纪律：分析只报告**已发生**的数据规律，不允许 AI 推导"我觉得会火"的预测性结论。

## 记录模板（一条故事一行）

```csv
故事编号,发布日期,标题,画风,光影#,画纸#,色彩笔触,醒图参数,专属标记位置,封面文案,结尾文案,浏览量,首图划走率,完整滑动率,点赞,评论,备注
```

字段说明：
- **故事编号**：自增，如 S01 / S02…
- **光影# / 画纸#**：脚本日志里的 `[变量] 光影#N / 画纸#N`（或 USAGE.json 的 history）。
- **色彩笔触**：本次生图 prompt 里的光影描述关键词（方便回顾当时氛围）。
- **醒图参数**：本文二次加工用的参数组合，如 `色温+6,颗粒+12`。
- **专属标记位置**：左下 / 右上 / 左上 / 右下。
- **封面文案 / 结尾文案**：首图钩子 / 尾图反转，分别记。
- **数据列**：从抖音创作者后台回填。

> **变量重复自查**：每次开跑前看 `USAGE.json`（skill 根目录）的 history 列表，
> 确认本次要用的光影&画纸序号**不在最近 3 条里**。脚本自动轮换已保证不连用，
> 但若你手动用 `--lighting` 覆盖过，需自行核对。

## 数据判定 → 优化方向

| 现象 | 可能原因 | 应对 |
|------|----------|------|
| 首图划走高 | 封面钩子不抓人 / 首图剧透 | 换更悬的封面文案，首图只留悬念不放结局 |
| 很少滑到尾图 | 中间图太多 / 旁白太密 | 精简到 3~6 张，中间字幕 2 行以内 |
| 评论量极低 | 结尾没留讨论空间 | 结尾用开放提问，不做封闭金句 |
| 持续低流量 | 变量组合重复 / 二次加工没执行 | 查 USAGE.json 撞参数没有；检查醒图步骤是否漏 |
| 流量断崖 | 疑似被限流 | 停更 1~2 天，换全新光影+画纸组合，AI 特征明显降低再发 |

## 复盘节奏

- 每 **10 篇** 回看一次：哪类光影氛围 + 哪类故事数据最好，总结成"爆款组合"。
- 连续 3 篇数据都不行：切换流程（换风格分支 / 换选题方向）。
